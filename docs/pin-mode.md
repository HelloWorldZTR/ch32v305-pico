# CH32V305 Pico Pin Layout

This board uses the Raspberry Pi Pico's 51 × 21 mm outline, dual 20-pin rows,
2.54 mm pin pitch, and 17.78 mm row spacing. The diagram below is oriented with
the **USB-C connector at the top**: the left row runs from Pin 1 to Pin 20, top
to bottom, and the right row runs from Pin 40 to Pin 21, top to bottom.

> This board is mechanically compatible with the Pico layout and follows its
> common interface conventions; it is not software-compatible with the RP2040.
> CH32V305 alternate functions depend on the AFIO remap configuration. The
> diagram shows the recommended common functions for this board, not every
> alternate-function combination in the datasheet.

## Recommended contiguous interface groups

- Primary UART: Pin 1 `PA2/USART2_TX` + Pin 2 `PA3/USART2_RX`.
- SPI1: Pin 7 `PA4/NSS`, Pin 9 `PA5/SCK`, Pin 6 `PA6/MISO`, and Pin 10 `PA7/MOSI`.
- Primary I²C: Pin 20 `PB10/I2C2_SCL` + Pin 19 `PB11/I2C2_SDA`.
- SPI2: Pin 17 `PB12/NSS`, Pin 21 `PB13/SCK`, Pin 22 `PB14/MISO`, and Pin 24 `PB15/MOSI`.
- Pico analog area: Pins 31, 32, and 34 are `ADC10`, `ADC11`, and `ADC12`; Pin 33 is `AGND`; Pin 35 is `ADC_VREF/VDDA`.

ADC inputs must never exceed VDDA or fall below VSSA. Do not treat ADC pins as
5 V-tolerant digital inputs.

## Internal expansion pads

The outer headers prioritize all 16 ADC channels. The remaining GPIOs may be
routed to internal test pads or a 0.5/1.0 mm-pitch FPC connector:

| Purpose | MCU GPIO (physical pin) |
|---|---|
| Onboard user LED | PA8/41, active high; TIM1_CH1 can provide PWM output |
| WCH-Link / SWD | Three pads on the underside, left to right: PA14/49 SWCLK, GND, PA13/46 SWDIO |
| USBFS alternative | PA11/44 USB1DM, PA12/45 USB1DP |
| High-speed/serial expansion | PA9/42, PA10/43, PA15/50 |
| SPI3 / SDIO | PC10/51, PC11/52, PC12/53, PD2/54, PB3/55, PB4/56, PB5/57 |
| I2C1 | PB8/61 SCL, PB9/62 SDA |
| RTC / LSE | PC13/2, PC14/3, PC15/4 |
| Boot | PB2/28 BOOT1, BOOT0/60 |

USBHS uses PB6/58 `USBHS_DM` and PB7/59 `USBHS_DP`. These signals may only be
exposed on very short, stub-free test pads; do not route them to ordinary pin
headers.

## Regenerating the pinout diagram

The diagram is generated by a small dependency-free Python script in this
repository:

```sh
python3 tools/render_pinout.py
```

To check that the committed SVG matches the script data:

```sh
python3 tools/render_pinout.py --check
```

When changing the pin assignment, update both `PINS` in
`tools/render_pinout.py` and the table on this page, then regenerate
`docs/assets/pinout.svg`.
